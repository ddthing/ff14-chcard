# 웹 접근성·UI 편의·저장 데이터 정리 설계

## 배경

현재 프로젝트는 건너뛰기 링크, 주요 landmark, 키보드 가능한 탭과 목록, 크롭 대화상자의 포커스 트랩, live region 등 접근성 기반을 갖추고 있다. 이번 작업은 현재 Nova/Neutral 디자인 계약과 카드 PNG 출력 형태를 유지하면서 남은 키보드 충돌, 사용자 지정 색상 대비, 비동기 오류 전달, 오래된 로컬 데이터와 코드 잔여물을 정리한다.

기존 작업 트리에 있는 미커밋 변경과 설계 문서는 사용자 작업으로 간주한다. 구현은 관련 줄만 수정하며, 기존 변경을 되돌리거나 덮어쓰지 않는다.

## 목표

- 선택된 스티커가 다른 편집 컨트롤의 키보드 입력을 가로채지 않게 한다.
- 일반 텍스트와 핵심 상태 표시가 WCAG 4.5:1 대비를 만족하도록 포인트 컬러 사용을 분리한다.
- 제목 구조, 포커스 표시, 진행 상태, 모달 복귀 포커스와 오류 안내를 일관되게 만든다.
- `prefers-reduced-motion`이 CSS와 Framer Motion 모두에 적용되게 한다.
- 기존 브라우저 프로필을 보존하면서 로컬 저장값을 검증·마이그레이션한다.
- 사용되지 않는 의존성·폰트·번역 키·문서 내용을 호환성 위험에 따라 단계적으로 정리한다.

## 선택한 접근

기존 구조를 유지하는 점진적 보강 방식을 사용한다.

1. 전역 이벤트를 늘리지 않고 스티커 키보드 처리를 미리보기의 명시적인 포커스 영역에 한정한다.
2. 사용자가 선택한 포인트 컬러 자체는 보존하되, 텍스트에는 배경별 접근성 색상을 계산해 사용한다. 대비가 부족한 입력에는 경고와 안전 색상 적용 기능을 제공한다.
3. 로컬 데이터는 강제 초기화하지 않는다. 알려진 필드만 정규화하고 유효한 사용자 텍스트·이미지·스티커는 보존한다.
4. 삭제와 저장 실패처럼 되돌리기 어려운 동작에는 확인보다 흐름을 덜 방해하는 Undo와 상태 메시지를 우선한다.
5. 시각 스타일은 `DESIGN.md`의 Nova/Neutral/Radius None 계약을 따르며 카드 출력 영역의 기존 시각 결과는 유지한다.

## 대안과 결정

### 전면 컴포넌트 교체

탭, listbox, modal을 외부 접근성 컴포넌트로 모두 교체하면 일관성은 높아지지만 기존 미커밋 작업과 카드 편집 흐름을 크게 흔든다. 이번 범위에서는 선택하지 않는다.

### 접근성 오류만 최소 수정

키보드 충돌과 heading만 수정하면 위험은 작지만 저장 데이터 손상, 비동기 오류, 색상 대비 문제가 남는다. 사용자 요청의 데이터 정리와 편의 기능 범위를 충족하지 못하므로 선택하지 않는다.

### 점진적 보강과 마이그레이션

현재 인터페이스와 저장 포맷을 최대한 보존하면서 입력 경계, 상태 전달, 데이터 검증을 추가한다. 회귀 위험과 사용자 편의의 균형이 가장 좋아 이 방식을 선택한다.

## 단계별 설계

### 1. 키보드·문서 구조·포커스 안전성

- 스티커 방향키·삭제 처리는 선택된 스티커 버튼 또는 미리보기 포커스 영역에서만 실행한다.
- `input`, `textarea`, `select`, 링크, 탭, combobox 등 다른 interactive element의 키 입력은 절대 가로채지 않는다.
- 홈 편집기 섹션 heading을 `h1 → h2` 순서로 정리한다.
- 모바일 이미지 버튼, 직업 일괄 버튼, range, 가이드 목차에 공통 `focus-visible` 표시를 적용한다.
- Suspense와 이미지 저장 상태는 이름 있는 status로 노출한다. 저장 중에는 저장 버튼의 중복 실행을 막는다.

사용자 편의 기능:

- 선택된 스티커에 방향키·Shift+방향키·Delete 조작 안내를 제공한다.
- 삭제한 스티커는 짧은 시간 동안 Undo할 수 있다.
- 크롭 모달을 닫으면 실제 업로드 버튼으로 포커스가 돌아간다.

### 2. 대비·가독성

- 배경과 포인트 컬러의 WCAG 상대 명도 대비를 계산하는 공용 유틸리티를 만든다.
- 포인트 컬러가 배경색이나 장식에는 그대로 쓰이더라도 일반 텍스트에는 접근 가능한 파생색을 사용한다.
- HEX 입력이 완성되지 않았거나 대비가 부족하면 `aria-invalid`, 설명 텍스트와 live 상태를 제공한다.
- 추천 색상 버튼은 흰색·어두운 배경 모두에서 경계가 식별되게 한다.

사용자 편의 기능:

- 현재 대비 등급과 비율을 즉시 표시한다.
- 한 번에 안전 색상으로 조정할 수 있는 버튼을 제공한다.

### 3. 로컬 저장 데이터와 코드 정리

- 프로필 스키마를 다음 버전으로 올리고 `unknown` 입력을 검증하는 정규화 함수를 둔다.
- 알 수 없는 직업, 폰트, 언어, 레이아웃, 범위를 벗어난 레벨·스티커 좌표를 안전한 값으로 정리한다.
- 오래된 `imagePosition`은 읽기 호환 후 새 저장값에서 제거한다.
- 슬롯에도 버전과 검증을 적용하고 저장 실패를 사용자에게 알린다.
- 레거시 폰트 ID는 마이그레이션에서 Pretendard로 대체한 뒤 로더와 CSS에서 제거한다.
- 사용되지 않는 `feather-icons`, Google Fonts 요청, 번역 키를 제거한다.
- `MAINTENANCE.md`, `README.md`, 필요한 경우 `CLAUDE.md`를 현재 구조와 일치시킨다.
- `.superpowers/`의 런타임 로그와 임시 HTML은 ignore 처리하되 설계 문서는 보존한다.

사용자 편의 기능:

- 프로필과 슬롯을 JSON으로 내보내고 다시 불러오는 백업 기능을 제공한다.
- 같은 이름의 슬롯은 새 항목 추가와 기존 항목 업데이트를 구분할 수 있게 한다.
- 저장 공간 부족이나 손상된 데이터 복구 시 어떤 항목이 제외됐는지 안내한다.

### 4. 이미지·스티커·모션

- 캐릭터 이미지에도 형식·크기·디코딩 오류 검증과 사용자 메시지를 추가한다.
- 큰 이미지는 크롭 전에 적정 크기로 축소하고 처리 중 버튼을 비활성화한다.
- Framer Motion은 사용자 reduced-motion 설정 시 layout spring을 제거한다.
- 스티커 포인터 조작은 pointer capture 또는 문서 수준 종료 처리를 사용해 카드 밖에서 포인터를 놓아도 종료되게 한다.
- 동적 스티커 이미지에는 안정적인 intrinsic size 정보를 저장하거나 렌더링 기본 크기를 제공한다.

사용자 편의 기능:

- 이미지 자동 압축, 처리 진행 상태, 다시 시도를 제공한다.
- 스티커 중앙 정렬·초기화와 삭제 Undo를 제공한다.

### 5. 다국어·가이드·콘텐츠

- 일본어 가로형·세로형 레이블과 영어 자기소개 placeholder를 교정한다.
- Contact, 언어 선택, 테마 설명 등 컴포넌트 내부 문자열을 중앙 번역 데이터로 이동한다.
- 자기소개에 현재 글자 수를 표시하고 보조기기에는 과도하게 자주 읽히지 않게 한다.
- 가이드 체크리스트 진행률을 polite live region으로 제공한다.

사용자 편의 기능:

- 문의 페이지에 FAQ 링크와 버그 제보용 기기·브라우저 정보 복사 기능을 제공한다.
- 외부 링크가 새 창에서 열리는 경우 이를 텍스트 또는 접근성 이름으로 알린다.

## 데이터 흐름

1. 브라우저 저장값을 `unknown`으로 읽는다.
2. 스키마 버전을 확인하고 이전 버전이면 migration을 적용한다.
3. 정규화 함수가 필드별 타입·허용값·범위를 검증한다.
4. 복구 가능한 사용자 콘텐츠는 유지하고 유효하지 않은 디자인 설정만 기본값으로 대체한다.
5. 복구나 저장 실패가 발생하면 편집을 막지 않는 status 또는 toast로 알린다.
6. 이후 저장은 새 스키마만 사용한다.

## 오류 처리

- 파일 읽기, 이미지 디코딩, 크롭, 내보내기, localStorage 저장 실패는 콘솔에만 남기지 않는다.
- 오류 메시지는 문제와 다음 행동을 함께 제공한다.
- 저장 공간 부족 시 이미지부터 제외하되, 두 번째 저장도 실패하면 성공으로 표시하지 않는다.
- JSON 가져오기는 부분 적용하지 않고 전체 검증 후 사용자 확인을 받아 반영한다.

## 비범위

- 카드 PNG의 레이아웃과 브랜드 표현을 전면 재설계하지 않는다.
- 서버, 계정, 클라우드 동기화 기능을 추가하지 않는다.
- 외부 접근성 UI 프레임워크로 전체 컴포넌트를 교체하지 않는다.
- 사용자의 기존 미커밋 변경이나 설계 문서를 정리 대상으로 간주하지 않는다.

## 검증

- `npm run lint`
- `npm run build`로 TypeScript, Vite 클라이언트, SSR, prerender 검증
- 키보드 수동 시나리오: 탭 이동, 직업 탭 방향키, 스티커 선택·이동·삭제·Undo, 모달 ESC·포커스 복귀
- 색상 대비 단위 검증: 추천 색상과 임의 HEX를 흰색·어두운 배경에 대조
- localStorage 회귀 시나리오: 정상 현재 버전, 이전 버전, 손상 JSON, 알 수 없는 직업·폰트, 저장 공간 부족
- reduced-motion 환경에서 Framer Motion layout 애니메이션 비활성 확인
- 모바일·데스크톱에서 이미지 업로드, 크롭, PNG 저장 smoke test

## 성공 기준

- 선택된 스티커가 다른 폼 컨트롤의 방향키·삭제 키를 방해하지 않는다.
- 핵심 편집 기능을 마우스 없이 실행할 수 있고 포커스가 항상 보인다.
- 포인트 컬러를 사용하는 일반 텍스트가 4.5:1 대비를 만족한다.
- 손상되거나 오래된 브라우저 데이터 때문에 앱 전체가 초기화되거나 중단되지 않는다.
- 실패한 저장·이미지 처리 작업이 성공으로 오인되지 않는다.
- `DESIGN.md`와 카드 출력의 구조·레이아웃을 보존하되 접근성에 필요한 텍스트 색상만 조정하고, lint와 production build가 통과한다.
