# 웹 접근성 우선순위 개선 설계

## 목표

KS X OT0003 2.1·2.2 검수에서 확인된 핵심 미준수 항목을 기존 Nova/Neutral UI와 i18n 구조를 유지하면서 단계적으로 개선한다. 이번 범위는 시각적 재설계가 아니라 키보드·보조기기·포커스·상태 전달을 우선한다.

## 선택한 접근

기존 동작을 유지하는 점진적 보강 방식을 사용한다.

- 이미지 업로드와 스티커 선택은 네이티브 버튼 또는 명시적인 `role="button"` 컨트롤로 노출한다.
- 포인터 기반 스티커 조작에는 키보드 대체 조작과 `pointercancel` 복구를 추가한다.
- 이미지 자르기 모달은 `role="dialog"`, 제목 연결, 초기·복귀 포커스, ESC 닫기, 포커스 트랩을 갖춘다.
- 직업 선택기는 현재 외형을 유지하되 `combobox/listbox/option` 관계, 선택 상태, 화살표 키 이동을 명시한다.
- 색상 대비는 YIQ 추정 대신 WCAG 상대 명도 대비를 사용한다.
- 토스트와 선택 상태는 `aria-live`, `aria-pressed`, `aria-selected`, 포커스 스타일로 전달한다.

## 단계

1. 핵심 키보드 조작: 이미지 업로드, 모바일 썸네일, 스티커 목록·캔버스 선택, 포인터 취소.
2. 이미지 자르기 모달: 대화상자 의미, 포커스 관리, ESC, 키보드 가능한 버튼 스타일.
3. 직업 선택기: 접근성 이름, listbox/option 관계, 키보드 탐색, inactive ARIA 참조 정리.
4. 대비·상태·선택: WCAG 대비 계산, 토스트 live region, 레이아웃/입력 포커스, 홈 제목 보강.
5. 모바일 선형 순서와 전체 회귀 검증.

## 비범위

- 카드 이미지 출력 디자인과 저장 이미지의 시각적 결과 변경
- 서버·데이터 모델·localStorage 형식 변경
- 접근성과 직접 관련 없는 대규모 컴포넌트 리팩터링

## 성공 기준

- 핵심 입력과 편집 기능을 마우스 없이 접근·실행할 수 있다.
- 모달이 열릴 때 포커스가 내부로 이동하고 닫힐 때 호출 컨트롤로 복귀한다.
- 커스텀 직업 선택기의 접근성 트리와 키보드 동작이 일치한다.
- 포인트 컬러 텍스트가 일반 텍스트 대비 4.5:1 이상을 만족하거나 안전한 색을 사용한다.
- lint, TypeScript/Vite build, production preview의 데스크톱·모바일 smoke test가 통과한다.
