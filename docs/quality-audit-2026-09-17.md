# 사이트 품질 개선 및 검증 기록

## 반영 내용

- Nova/Neutral 계약을 유지하면서 편집기 제목, 미리보기 도구 영역, 캔버스 배경을 정리했다. 모바일에는 편집/미리보기 전환과 미리보기 내 저장 버튼을 추가했다.
- 입력 후 250ms 이내에 페이지를 떠날 때 저장이 누락되는 문제를 재현했다. `pagehide`, 문서 비활성화, Provider 정리 시 대기 중인 저장을 수행한다.
- 카드의 transform 안에서 자르기 모달이 카드 크기에 갇히는 문제를 재현했다. 모달을 body portal로 옮기고 배경 inert, 포커스 복귀, 취소 후 비동기 결과 무시를 적용했다.
- 선택한 스티커의 이미지까지 `export-ignore`로 제외되는 문제를 재현했다. 선택 테두리와 조작 UI만 제외하며 이미지 자체는 저장한다.
- 비동기 스티커 업로드가 이전 배열을 덮어쓰지 않도록 함수형 상태 갱신을 사용했다. 중복 ID 복원 및 0으로 나누는 변형 계산도 보강했다.
- 백업의 형식, 버전, 슬롯, 프로필 구조를 기존 데이터 교체 전에 검증한다. 잘못된 파일과 20MiB 초과 파일은 거부한다.
- 자르기 라이브러리를 지연 로딩한다. 전체 원본 캔버스와 별도 ImageData 복사 대신 크롭 영역에 직접 그린다.
- PNG의 두 패스에서 폰트 임베딩을 재사용하며 원본 DOM의 transform을 변경하지 않는다. 중복 내보내기도 방지한다.
- 홈과 알림 컴포넌트의 상태 구독 범위를 줄이고 동일한 필드 값 갱신을 건너뛴다.
- 언어 선택 버튼의 명도 대비 부족을 수정했다.

## 검증 결과

| 검사 | 결과 |
| --- | --- |
| ESLint | 통과 |
| TypeScript + Vite client/SSR build | 통과 |
| 정적 페이지 생성 | guide, about, faq, contact, terms, privacy 생성 |
| 브라우저 회귀 검사 | 27개 통과 |
| PNG 출력 | 데스크톱 1400px, 모바일 1050px 너비 생성 확인 |
| 선택된 스티커 출력 | 실제 PNG 중앙 픽셀 `[41,94,155,255]`로 테스트 스티커 포함 확인 |
| 반응형 | 320, 390, 768, 1024, 1440px 확인; 검사한 화면에서 가로 넘침 없음 |
| 언어/테마 | 한국어·영어·일본어 전환, 모바일 다크 모드 확인 |
| Lighthouse 모바일 snapshot | 접근성 100, Best Practices 100, SEO 100 |

Lighthouse 수치는 로컬 Chrome의 검사한 화면 기준이며 전체 사이트/모든 상태의 보증이 아니다. 별도 Agentic Browsing 항목은 llms.txt 부재로 50점이며 이번 편집기 개선 범위에 포함하지 않았다. Firefox/Safari 실기기 검증 및 배포는 수행하지 않았다.

## 회귀 검사 재실행

`npm run dev` 실행 후 **사용자 프로필이 없는 격리된 브라우저 컨텍스트**의 홈 화면에서 다음 코드를 실행한다. 이 검사는 이름을 변경하고 테스트 스티커를 추가하므로 실제 사용 중인 프로필에서 실행하지 않는다.

```js
await (await import('/scripts/quality-regression.mjs')).runQualityChecks()
```

검사는 백업 파서, 중복 ID, 이미지 크롭의 픽셀 동등성, 페이지 이탈 저장, 모달 범위/포커스/inert, 처리 중 취소, 동시 업로드, 선택 스티커의 저장 포함 여부, 잘못된 백업의 데이터 보존을 확인한다.

검증 중 스크린샷용 프로필 교체 요청은 자동 승인 검토에서 저장 데이터 덮어쓰기 우려로 거부되어 생략했다. 나머지 검증은 현재 테스트 상태에서 수행했다.
